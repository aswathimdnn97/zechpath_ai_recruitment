# AI Screening Data Structure

## 1. Purpose

This document describes how data moves through the ZechPath AI Recruitment HR screening workflow, from session creation and question assignment to candidate responses, transcript processing, evaluation, and recruiter review.

## 2. Main Data Entities

| Entity | Responsibility |
|---|---|
| Candidate | Represents the person participating in screening |
| Job | Represents the position for which screening is conducted |
| Screening Session | Tracks a candidate's screening attempt |
| Question | Stores configured screening questions |
| Session Question | Records which questions are assigned to a session and their order |
| Screening Response | Stores a candidate's answer to an assigned question |
| Transcript | Stores speech-to-text output and its processing and review information |
| Evaluation | Stores the session-level evaluation result |
| Evaluation Detail | Stores evaluation information for an individual question |
| Recruiter Review | Records the recruiter's decision and comments |

## 3. Relationship Overview

A screening session connects the candidate, job, and screening process.

- A screening session can contain multiple assigned questions.
- Each assigned question can have a corresponding screening response.
- A transcript can be linked to a screening session and, when applicable, a screening response.
- A screening session can have evaluation records.
- An evaluation can contain multiple question-level evaluation details.
- Recruiter reviews can be associated with a session and its evaluation.

The implemented database uses `session_questions` to represent assigned questions and `screening_responses` to store answers.

## 4. Screening Data Flow

1. **Create session:** Establish the candidate's screening session and associate it with the job, role, and language.
2. **Assign questions:** Create question assignments with ordering and mandatory-question information.
3. **Collect responses:** Save answers and track draft or submitted response states.
4. **Process voice transcripts:** Store recognized text, normalized text, metadata, and processing status.
5. **Review transcripts:** Approve or correct transcript text where the workflow requires review.
6. **Evaluate screening:** Evaluate submitted sessions using objective answer keys and the applicable review process for open-ended answers.
7. **Store evaluation:** Save the session-level evaluation and question-level details.
8. **Recruiter review:** Record the recruiter's decision and comments.

## 6. Data Integrity

The database enforces relationships between sessions, assigned questions, responses, evaluations, and questions through primary keys, foreign keys, unique constraints, and check constraints.

Application services must also validate workflow rules, including session ownership, question assignment, mandatory-answer completeness, submission state, and transcript review requirements.

## 7. Evaluation and Recruiter Review

Evaluation records capture the result of screening. Evaluation details hold per-question information such as score, maximum score, evaluation status, and feedback.

Recruiter review records capture a human decision, including the configured decision values:

- `SHORTLIST`
- `REJECT`
- `HOLD`
- `NEEDS_FURTHER_REVIEW`

Automated evaluation and recruiter review are separate stages. The existence of a score does not by itself represent a final recruiter decision.

## 9. Design Principle

Each entity has a distinct responsibility. Separating sessions, assigned questions, responses, transcripts, evaluation records, and recruiter reviews improves traceability and makes the screening workflow easier to validate and maintain.
